## 2. Архитектура / подход

Сохранить React/Vite, текущий визуальный язык и Python/FastAPI: добавить тонкий Telegram-адаптер, подключить уже имеющиеся доменные функции и заменить локальные имитации реальными небольшими API. Один HTTPS origin обслуживает SPA и `/api`, один polling-бот принимает Telegram updates, одна SQLite на постоянном диске хранит данные приложения; никакие PostgreSQL/Redis/новая CMS/AI-сервисы не нужны для этого релиза. Сервер является источником identity, опубликованного контента, пользовательских записей и прав; браузер не может сам выдать себе Premium или административную роль.

### Решения, которые исполнитель не выбирает заново

1. Hash-router сохранить. Не вводить React Router ради переписывания навигации.
2. Авторизация: проверить свежий `initData` при входе, затем выдать непрозрачную серверную сессию. Не заставлять человека переоткрывать приложение каждые пять минут и не хранить bot token/JWT в браузере.
3. Production API и SPA на одном origin: без `CORS *`, без cross-origin cookies. HTTPS завершает reverse proxy, Uvicorn слушает loopback.
4. Новую app-схему хранить отдельно от legacy `bot/keto_balance.db`: `APP_DB_PATH` на приватном постоянном диске. Это сохраняет старые данные. Общая app-БД используется API и ботом; WAL, короткие транзакции, отдельное соединение на операцию.
5. Каталог: первоначальный seed из `src/data/recipes.ts`, далее источник опубликованных версий — SQLite. Seed не переписывает редактуру владельца и не публикуется автоматически.
6. Старые `init_purchase`, `complete_demo_payment`, бессрочные legacy-флаги и `/api/payments/webhook` остаются отключёнными. Новая Stars-цепочка — `bot/billing.py`, а не включение старого demo.
7. Сессия — 24 часа, в БД только SHA-256 случайного токена; cookie HttpOnly/Secure/SameSite=Lax. Изменения дополнительно требуют допустимого Origin и CSRF token, привязанного к сессии. HTTP допускается только в отдельном loopback-тестовом запуске.
8. Рецепты/меню — кулинарные варианты с ограничениями, без индивидуальных целей калорий/БЖУ. Непроверенные нутриенты скрываются или [УТОЧНИТЬ]; новые медицинские формулы не писать.
9. Один выбранный visual reference, не три новых дизайна. Максимум два согласованных круга визуальных поправок; после утверждения — только исправление измеримых дефектов.

### 3.4 Чем продукт отличается и за что платят

Не «ещё одна папка рецептов», а быстрый переход от решения что приготовить к реальной закупке и следующей удобной неделе. Разовая программа даёт законченный небольшой результат; подписка сохраняет рабочие шаблоны, позволяет перепланировать и повторно использовать подходящие блюда. Личные записи, купленные материалы и сохранённые результаты не становятся заложниками продления.

Предложение для одного коммерческого согласования: `free`, разовый `start` на 7 дней инструментов с постоянным чтением приобретённых материалов, `month` на 30 дней с автопродлением. Срок start=7 дней — предложение этого плана, не уже утверждённое владельцем условие. Цена XTR по умолчанию `null`, покупка отключена до утверждения; не подставлять старые 49/199/299 Stars или 390/1900 ₽. Все обещанные функции видимы в бесплатном примере честно, платный результат не подменён заглушкой.

2. Если новый модуль отсутствует, ImportError доказывает только отсутствие модуля; после минимального контракта получить падение нужного утверждения. Не выдавать случайный KeyError/ошибку стенда за воспроизведённый дефект.
3. Сделать минимальную правку перечисленных файлов; для узких новых узлов использовать полный код приложений ниже.
4. Повторить ту же команду: ожидаются exit 0, нужные тесты действительно собраны, нет обязательных skipped. Затем соседний regression-набор и typecheck для TS.
5. Маленький scoped commit — только если владелец отдельно разрешил коммиты: `git add -- <только перечисленные файлы>` и тематический `git commit`. Иначе оставить проверенный diff; не коммитить чужие изменения, `.env`, БД, логи и приватные фикстуры. Push/deploy отдельно не разрешены.

Каждый микрошаг — 2–5 минут фокуса: один RED-кейс и его запуск; затем одна минимальная правка и повтор; затем соседняя регрессия. Строки таблиц ниже — пакеты этих микрошагов, а не обещание реализовать весь CRUD или экран за пять минут. Для больших пакетов обязательная конечная разбивка приведена в приложении I: конкретный endpoint/экран/поле, один тест, та же команда. Исследование источников, ожидание согласования, загрузка браузеров, настройка сервера и проверка устройства не оцениваются искусственно в пять минут. Не добавлять новые возможности при декомпозиции. Два неудачных исправления одного места → перечитать текущий файл; не бесконечно чинить устаревший контекст.

## 6. Новая app-схема и контракты repository

Не изменять legacy-таблицы ради этого релиза. Новая schema v1 в `bot/app_db.py`, новая отдельная SQLite по `APP_DB_PATH`; миграции production — только с ручным согласованием/проверенным backup. Даты хранения — UTC Unix seconds, локальный день пользователя — ISO date с отдельно сохранённым timezone.

Repository: `AppRepository(path)` без I/O; `initialize()` только явно; `transaction()` с BEGIN IMMEDIATE для конкурентной оплаты/ревизий; `get_document(user_id,kind)`, `put_document(user_id,kind,expected_revision,payload)`, `save_diary(...)`, `get_session(...)`, `publish_content(...)`, `apply_payment(...)`, `create_ticket(...)`. Эти методы новые: реализовать по таблицам и указанным тестам, не выдумывать существующий API.

В production cookie назвать `__Host-kb_session`, Secure/HttpOnly/Path=/, без Domain. Только отдельный loopback helper использует `kb_session_test` без Secure; production settings не допускают такой fallback. CSRF nonce хранится как nonce, не как невосстановимый hash: `/api/session` после reload возвращает его только текущей авторизованной сессии; cookie bearer хранится только хешированным. Самоподтверждение 18+ не называть документальной проверкой возраста.

В обычном браузере без initData разрешён только явно подписанный «Пример» с публичными синтетическими данными. Не создавать demo-user для private API. Настоящая админка на ПК открывается в Telegram Desktop с проверенной identity; отдельный web-login в v1 не добавлять.

При UPDATE сначала проверка владельца и revision в одной транзакции. Не переносить весь старый `store` одним blob; premium/admin/chat/consult не становятся пользовательскими серверными правами. Удаление аккаунта удаляет/анонимизирует согласованные данные по утверждённой политике; платёжный минимум хранить отдельно только после определения законных условий, не обещать «всё удалено», если остаётся обязательная запись.

### Отправка напоминаний

Один worker в polling-боте, не отдельный бесконечный агент. Уникальный ключ предотвращает штатные повторы. Выбрать для некритичного напоминания консервативную at-most-once-attempt политику: атомарно reserve/attempt перед отправкой; подтверждённый отказ Telegram можно перенести, неопределённый сетевой исход — unknown без автоматического повтора, показать владельцу. Не обещать exactly-once между SQLite и внешним API. `allow_paid_broadcast=False`; никакой массовой рассылки.

## 7. API: точные правила, чтобы не угадывать

Все private-запросы — с cookie-сессией; unsafe методы также Origin и `X-CSRF-Token`. Один envelope: успех `{data:..., revision?:number}`, ошибка `{error:{code,message,details?:...}}`. Не возвращать initData, cookie, stack trace, чужие данные. JSON body extra=forbid, request size ограничить 256KiB, ticket text 4000, profile custom note 500; ограничения — технические, без медицинских назначений.

| Метод/путь | Вход / выход / авторизация |
|---|---|
| GET /api/bootstrap | public: release, доступные free примеры, версии документов, payments_available. Без приватных данных |
| POST /api/auth/telegram | raw init_data, adult_confirmed, принятые версии service/privacy. HMAC→identity; cookie + data:{user_id,is_admin,csrf_token,access}. Нет подписи401, отказ 18+/версий422 |
| GET /api/session | current session user/access/CSRF; no session401 |
| POST /api/auth/logout | revoke current session, clear cookie, 204 |
| GET/PATCH /api/me/profile | ProfileDTO + expected_revision; mismatch409 |
| GET/PUT /api/me/documents/{kind} | конкретная DTO + expected_revision, собственник от сессии; ID из body запрещён |
| GET/PUT /api/me/diary/{YYYY-MM-DD} | DiaryDTO + expected_revision; sensitive-поля только с отдельным согласованным разрешением |
| GET /api/me/export | свои согласованные данные JSON; no-store |
| DELETE /api/me | явное подтверждение, удаление по политике, revoke sessions, 204 |
| GET /api/catalog, /api/lessons | только опубликованные и доступные данному уровню; платный контент не попадает в anonymous bundle |
| GET /api/products | единый утверждённый каталог без возможности менять цену клиентом |
| POST /api/billing/invoices | sku + idempotency_key + terms consent, без amount/user_id; unavailable503, access-conflict409 |
| POST /api/billing/subscription/cancel | своя root subscription, CSRF, confirmed cancellation или pending; оплаченный срок не срезается |
| GET/POST /api/me/tickets | свои обращения; own_order_id проверяется сервером |
| POST /api/me/tickets/{id}/messages | свой ticket, plain text, чужой ID403/404 |
| GET/PUT /api/me/reminder | preference DTO, revision; единственный menu-shopping тип |
| GET/PUT /api/admin/content/{kind}/{id} | require_admin, draft + expected_revision; публикация отдельным POST .../publish |
| GET/POST /api/admin/tickets/{id}/messages | require_admin; медицинские записи в ответ не подмешиваются |
| GET /api/version, /api/health | public technical metadata/no personal data; index/version Cache-Control no-store |

`ProfileDTO`: mode keto/carnivore; adult_confirmed; meals 2/3/4; known allergies/disliked arrays; custom allergyNote; cookTime 15/30/60; prep bool; budget economy/ordinary/flexible; optional nickname. Медицинские документы, диагноз, пол/рост/вес для генерации не нужны.

`MenuDTO`: прежние mode/numDays/meals/portion/saved/created/days; days[].date; slots — независимые breakfast/lunch/dinner/snack → recipe ID. Сохранять договорённый ID-контракт. Явный пропуск блюда хранить отдельно от его категории, не превращать другой рецепт в новый слот.

`ShoppingDTO`: derived и manual раздельно, checked по стабильным ключам. Новое поле количества — `quantity: number | null`, не старое `qty`. Все чтения `i.qty.toFixed(...)` в App заменить форматтером через `Intl.NumberFormat('ru-RU', {maximumFractionDigits:2})`; null показывает исходную note, а не 0. Ручная строка без введённого количества не превращается автоматически в «1 шт». Legacy qty переносится только как явно непроверенное старое значение/подпись. API не принимает цены/права из строки покупок. Каждый derived row содержит source recipe IDs/порции; неизвестная мера сохраняет исходную подпись. Изменение количества снимает отметку «куплено» этой строки и показывает изменение, не сбрасывает весь список.

`DiaryDTO`: nullable meal notes/recipe references, optional weight/measurements/wellbeing/habits, note; пустые шкалы не равны средней оценке. Body не включает owner_id, role, premium и произвольный store.

### Приложение E. Безопасные количества покупок

Новый `src/domain/shopping.ts` — минимальная совместимость с существующим Recipe.ing; затем structured editor сохраняет канонические меры. Не конвертировать ложки/банки в граммы по догадке.

```ts
import type { Recipe, GeneratedMenu } from './types';

export type Amount = { quantity: number | null; unit: string; original: string };
export type ShoppingRow = {
  id: string;
  name: string;
  quantity: number | null;
  unit: string;
  notes: string[];
  sourceRecipeIds: string[];
};

export function parseAmount(original: string): Amount {
  const text = original.trim().toLowerCase().replace(/ё/g, 'е');
  const match = text.match(/^(\d+(?:[.,]\d+)?)\s*(кг|г|л|мл|шт)\.?$/u);
  if (!match) return { quantity: null, unit: '', original };
  const number = Number(match[1].replace(',', '.'));
  if (!Number.isFinite(number) || number <= 0) throw new Error('Некорректное количество ингредиента');
  const rawUnit = match[2];
  const factor = rawUnit === 'кг' || rawUnit === 'л' ? 1000 : 1;
  const unit = rawUnit === 'кг' ? 'г' : rawUnit === 'л' ? 'мл' : rawUnit;
  return { quantity: number * factor, unit, original };
}

export function buildShopping(menu: GeneratedMenu, recipes: Recipe[]): ShoppingRow[] {
  if (!Number.isFinite(menu.portion) || menu.portion <= 0) throw new Error('Некорректные порции');
  const rows = new Map<string, ShoppingRow>();
  for (const day of menu.days) {
    for (const id of Object.values(day.slots)) {
      const recipe = recipes.find(item => item.id === id);
      if (!recipe) throw new Error(`Рецепт недоступен: ${id}`);
      if (!Number.isFinite(recipe.serv) || recipe.serv <= 0) throw new Error('Не указаны порции рецепта');
      for (const [rawName, rawAmount] of recipe.ing) {
        const name = rawName.trim();
        if (!name) throw new Error('Пустой ингредиент');
        const amount = parseAmount(rawAmount);
        const normalizedName = name.toLocaleLowerCase('ru').replace(/ё/g, 'е');
        const suffix = amount.quantity === null ? `unknown:${recipe.id}:${rawAmount}` : amount.unit;
        const key = `${normalizedName}|${suffix}`;
        let row = rows.get(key);
        if (!row) {
          row = { id: key, name, quantity: amount.quantity === null ? null : 0, unit: amount.unit, notes: [], sourceRecipeIds: [] };
          rows.set(key, row);
        }
        if (amount.quantity === null) {
          row.notes.push(`${recipe.title}: ${rawAmount} на ${recipe.serv} порц.; выбрано ${menu.portion}`);
        } else {
          row.quantity = (row.quantity ?? 0) + amount.quantity * menu.portion / recipe.serv;
        }
        if (!row.sourceRecipeIds.includes(recipe.id)) row.sourceRecipeIds.push(recipe.id);
      }
    }
  }
  return [...rows.values()].sort((a, b) => a.name.localeCompare(b.name, 'ru'));
}
```

Пропуски блюд, если вводятся в MenuDTO, перед вызовом явно исключаются из разрешённого списка slots отдельным адаптером; не молча добавлять нулевые ID. `portion` здесь = число людей/порций на каждый выбранный приём; `recipe.serv` = выход полного рецепта. В UI это объяснить. Дробное необходимое количество не округляется скрыто до покупки упаковки; округление упаковок — отдельная будущая функция.

### Приложение F. Проверка Telegram initData без стороннего auth-сервиса

Полный новый `bot/auth.py` для чистой проверки подписи; session/dependencies добавляются D04 поверх этого, не вместо него:

```python
import hashlib
import hmac
import json
import re
import time
from urllib.parse import parse_qsl

class AuthError(ValueError):
    """Invalid Telegram launch data; never include raw input in logs."""


def verify_init_data(raw: str, bot_token: str, *, now: int | None = None, max_age: int = 300) -> int:
    if not bot_token:
        raise AuthError('Authentication is not configured')
    if not isinstance(raw, str) or not raw or len(raw) > 8192:
        raise AuthError('Invalid launch data')
    if re.search(r'%(?![0-9a-fA-F]{2})', raw):
        raise AuthError('Invalid URL encoding')
    try:
        pairs = parse_qsl(raw, keep_blank_values=True, strict_parsing=True, encoding='utf-8', errors='strict')
    except (ValueError, UnicodeError) as exc:
        raise AuthError('Invalid launch data') from exc
    if len(pairs) != len({key for key, _ in pairs}):
        raise AuthError('Duplicate launch fields')
    fields = dict(pairs)
    supplied = fields.pop('hash', '')
    if not re.fullmatch(r'[0-9a-fA-F]{64}', supplied):
        raise AuthError('Invalid hash')
    check_string = '\n'.join(f'{key}={value}' for key, value in sorted(fields.items()))
    secret = hmac.new(b'WebAppData', bot_token.encode('utf-8'), hashlib.sha256).digest()
    expected = hmac.new(secret, check_string.encode('utf-8'), hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, supplied.lower()):
        raise AuthError('Invalid signature')
    stamp = fields.get('auth_date', '')
    if not re.fullmatch(r'[0-9]{1,12}', stamp):
        raise AuthError('Invalid auth date')
    current = int(time.time()) if now is None else now
    age = current - int(stamp)
    if age < -30 or age > max_age:
        raise AuthError('Expired launch data')
    try:
        user = json.loads(fields['user'])
    except (KeyError, ValueError, TypeError) as exc:
        raise AuthError('Invalid user') from exc
    if not isinstance(user, dict):
        raise AuthError('Invalid user')
    user_id = user.get('id')
    if type(user_id) is not int or user_id <= 0 or user_id >= 2 ** 53:
        raise AuthError('Invalid user identifier')
    return user_id
```

HMAC-ветка исключает только hash, сохраняя подписанное поле signature; не перепутать с отдельной Ed25519 third-party-веткой, где другой data-check-string. Синтетический token ниже не настоящий секрет.

### Приложение G. Policy runner без рекурсивных прогонов

Обязательный интерфейс нового `scripts/verification.py`:

- `Step(name, command, required_paths, kind)` — immutable dataclass.
- `build_plan(root: Path, stage: str) -> list[Step]` — чистая функция; неизвестный stage отклоняется.
- `validate_plan(root, steps)` — отсутствующая обязательная suite, package script, dependency или config → исключение/exit1 до subprocess.
- `run_step(step, root, env)` — `subprocess.run(..., shell=False)`; returncode сохраняется. Для node TAP parses `# tests`, `# fail`, `# skipped`; required skips/0tests блокируют. Для Playwright parses JSON report; любой unexpected/skipped/zero selected блокирует.
- `main` не вызывается из unit-теста production tree. Policy-tests создают временную структуру и подменяют run_step; отдельный настоящий subprocess допускается только на минимальном синтетическом child-command с известным exit.
- Полный backend запускается `scripts/run_backend_tests.py`, а не парсингом «файл существует».

Ниже полный `scripts/verification.py` для перечисленных режимов. Списки расширять только вместе с соответствующей задачей, не заменять проверку заглушкой или массовым skip.

```python
import argparse
import json
import os
import re
import subprocess
import sys
from dataclasses import dataclass
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent

class GateError(RuntimeError):
    """A required verification cannot be accepted."""

@dataclass(frozen=True)
class Step:
    name: str
    command: tuple[str, ...]
    required_paths: tuple[str, ...]
    kind: str = 'command'

P0_BACK = ('test_import_safety', 'test_database', 'test_payments_disabled',
           'test_payment_callbacks', 'test_server_security', 'test_safety', 'test_verify_script')
P0_FRONT = ('harness', 'catalog', 'eligibility', 'menu', 'replacement', 'honesty', 'safety')
VIS_BACK = ('test_verify_script', 'test_server_security', 'test_release_version')
VIS_FRONT = ('routes', 'telegram')
FREE_BACK = ('test_auth', 'test_app_settings', 'test_app_db', 'test_session_api',
             'test_app_models', 'test_user_api', 'test_data_rights', 'test_catalog_api',
             'test_admin_api', 'test_content_publication', 'test_support',
             'test_reminders', 'test_release_boundaries', 'test_safety_routing', 'test_log_redaction')
FREE_FRONT = ('routes', 'telegram', 'shopping', 'calendar', 'legacy', 'preferences')
PAID_BACK = ('test_products', 'test_billing_orders', 'test_stars_handlers',
             'test_entitlements', 'test_subscription_lifecycle', 'test_release_gate',
             'test_backup_restore')
VIS_E2E = ('layout', 'navigation', 'onboarding', 'visual')
FREE_E2E = VIS_E2E + ('p0', 'menu-flow', 'shopping', 'diary', 'support', 'persistence', 'admin')


def build_plan(root: Path, stage: str) -> list[Step]:
    if stage not in {'checkpoint', 'p0', 'visual', 'free', 'paid'}:
        raise GateError('Unknown verification stage')
    npm = 'npm.cmd' if os.name == 'nt' else 'npm'
    if stage == 'visual':
        back, front, specs = VIS_BACK, VIS_FRONT, VIS_E2E
    else:
        back, front = P0_BACK, P0_FRONT
        specs = ('p0',)
        if stage in {'free', 'paid'}:
            back += FREE_BACK
            front += FREE_FRONT
            specs = FREE_E2E
        if stage == 'paid':
            back += PAID_BACK
            specs += ('billing',)
    back_paths = tuple(f'tests/backend/{name}.py' for name in back)
    front_paths = tuple(f'tests/frontend/{name}.test.cjs' for name in front)
    back_cmd = [sys.executable, '-B', 'scripts/run_backend_tests.py']
    if stage == 'visual':
        back_cmd += ['--suite'] + [f'tests.backend.{name}' for name in back]
    front_cmd = ('node', '--test', '--test-reporter=tap', *front_paths) if stage == 'visual' else (npm, 'run', 'test:unit')
    steps = [
        Step('Backend', tuple(back_cmd), ('scripts/run_backend_tests.py',) + back_paths, 'backend'),
        Step('Frontend', tuple(front_cmd), front_paths, 'tap'),
        Step('Typecheck', (npm, 'run', 'typecheck'), ('tsconfig.json',)),
        Step('Build', (npm, 'run', 'build'), ('scripts/stamp-release.mjs',)),
    ]
    if stage != 'checkpoint':
        config = 'playwright.full.config.ts' if stage in {'free', 'paid'} else 'playwright.config.ts'
        spec_paths = tuple(f'tests/e2e/{name}.spec.ts' for name in specs)
        steps.append(Step('E2E', ('npx.cmd' if os.name == 'nt' else 'npx', '--no-install',
                                'playwright', 'test', f'--config={config}', *spec_paths),
                          (config,) + spec_paths, 'playwright'))
    return steps


def validate_plan(root: Path, steps: list[Step]) -> None:
    missing = [path for step in steps for path in step.required_paths if not (root / path).is_file()]
    if missing:
        raise GateError('Missing required files: ' + ', '.join(sorted(set(missing))))
    try:
        package = json.loads((root / 'package.json').read_text(encoding='utf-8'))
    except (OSError, ValueError) as exc:
        raise GateError('Invalid package.json') from exc
    scripts = package.get('scripts', {})
    for script in ('test:unit', 'typecheck', 'build'):
        if not scripts.get(script):
            raise GateError(f'Missing npm script: {script}')
    if any(step.kind == 'playwright' for step in steps):
        if not scripts.get('test:e2e'):
            raise GateError('Missing npm script: test:e2e')
        if '@playwright/test' not in package.get('devDependencies', {}):
            raise GateError('Missing declared Playwright dependency')


def assert_report(kind: str, output: str, root: Path) -> None:
    if kind == 'backend':
        match = re.search(r'BACKEND_RESULT tests=(\d+) failures=(\d+) errors=(\d+) skipped=(\d+)', output)
        if not match or int(match[1]) <= 0 or any(int(match[i]) for i in (2, 3, 4)):
            raise GateError('Invalid, empty, failed or skipped backend collection')
    elif kind == 'tap':
        values = {}
        for name in ('tests', 'fail', 'cancelled', 'skipped', 'todo'):
            match = re.search(rf'(?m)^# {name} (\d+)\s*$', output)
            if not match:
                raise GateError(f'Missing TAP summary: {name}')
            values[name] = int(match[1])
        if values['tests'] <= 0 or any(values[key] for key in ('fail', 'cancelled', 'skipped', 'todo')):
            raise GateError('Empty, failed or incomplete frontend collection')
    elif kind == 'playwright':
        try:
            report = json.loads((root / 'test-results/e2e.json').read_text(encoding='utf-8'))
            stats = report['stats']
            if stats['expected'] <= 0 or any(stats[key] for key in ('unexpected', 'flaky', 'skipped')):
                raise GateError('Empty, failed, flaky or skipped E2E collection')
        except (OSError, ValueError, KeyError, TypeError) as exc:
            raise GateError('Missing or invalid E2E report') from exc


def run_step(step: Step, root: Path, env: dict[str, str] | None = None) -> None:
    merged = os.environ.copy()
    merged.pop('PYTHONPATH', None)
    if env:
        merged.update(env)
    merged.update(KETO_LOAD_DOTENV='0', PYTHONDONTWRITEBYTECODE='1', PAYMENT_MODE='disabled',
                  PAYMENTS_ENABLED='0', APP_STAGE='test')
    if step.kind == 'playwright':
        (root / 'test-results/e2e.json').unlink(missing_ok=True)
    result = subprocess.run(step.command, cwd=root, env=merged, capture_output=True,
                            text=True, encoding='utf-8', errors='replace', shell=False)
    print(result.stdout, end='')
    print(result.stderr, end='', file=sys.stderr)
    if result.returncode:
        raise GateError(f'{step.name} failed with exit code {result.returncode}')
    assert_report(step.kind, result.stdout + '\n' + result.stderr, root)


def main(default_stage: str = 'p0') -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument('--stage', choices=['visual', 'free', 'paid', 'p0'], default=default_stage)
    parser.add_argument('--checkpoint', nargs='?', const='current')
    args = parser.parse_args()
    stage = 'checkpoint' if args.checkpoint is not None else args.stage
    try:
        steps = build_plan(ROOT, stage)
        validate_plan(ROOT, steps)
        for step in steps:
            print(f'[RUN] {step.name}')
            run_step(step, ROOT)
    except (GateError, OSError) as exc:
        print(f'[BLOCKED] {exc}', file=sys.stderr)
        return 1
    if stage == 'checkpoint':
        print('[CHECKPOINT PASSED] Not a full release approval')
    else:
        print(f'[TECHNICAL STAGE PASSED] {stage}; external/business approvals remain separate')
    return 0
```

### Приложение H. Платёжные правила без старого demo

Подтверждено официальной документацией в ходе планирования: цифровые продажи внутри Telegram — XTR; `createInvoiceLink.subscription_period` для recurring сейчас 2592000; `SuccessfulPayment` содержит trusted expiration, charge и recurring flags; cancel extension сохраняет текущий оплаченный период. Установленный PTB22.8 поддерживает create_invoice_link(subscription_period=...), но новый subscription update проверить отдельно.

Алгоритм нового `apply_payment` (не использовать legacy mark_order_paid):

1. До транзакции разобрать Telegram update валидированным DTO, user ID взять из Telegram update, не invoice/body.
2. BEGIN IMMEDIATE; найти order по opaque payload; сверить user, XTR, integer amount и immutable snapshot, разрешённое состояние.
3. Если charge уже существует — вернуть существующий access без повторной выдачи.
4. Для start рассчитать срок по утверждённому SKU серверным clock; для recurring использовать `subscription_expiration_date` из подтверждённого события, не добавлять 30 дней за каждый retry.
5. Записать payment event; обновить единственную subscription/access запись; commit. Сбой между действиями откатывает обе.
6. Первый root_charge_id сохранить для API отмены; последующие recurring charge связаны с исходным order/ценой. Смена каталога не переписывает старые условия.
7. Late/duplicate/out-of-order refunded/canceled updates не возвращают отозванное право без нового законного платежа. Срок от более старого события не уменьшает новый оплаченный срок.
8. Клиентский `invoiceClosed=paid` означает «проверяем», затем GET session/access; не меняет premium самостоятельно.
9. Возврат имеет requested/confirmed/unknown; Telegram timeout — unknown, не success. Поддержка видит необходимость сверки.

Для каждого: вход через настоящую HTTPS WebApp-кнопку; первый запуск/повторный вход; светлая тема и явная смена; ширина/безопасные края; экранная клавиатура; Back/sheet/close; recipe/menu/shopping; сохранение/возврат; потеря связи; доступность поддержки; корректная сумма/отмена в отдельно разрешённом тестовом платеже.

Не обновлять screenshots автоматически ради зелёного CI. При отсутствии устройства писать NOT VERIFIED, а не PASS.

### Финальный критерий остановки работ над v1

- G1: утверждён исходный визуальный характер и реальная Telegram-адаптация, один releaseId.
- G2: без помощи исполнителя пользователь проходит полезный путь, сохраняет/возобновляет данные, владелец управляет опубликованным контентом и реальной поддержкой.
- G3: доступ продаётся и выдаётся корректно, продление/отмена/возврат проверены, документы и выплаты подтверждены, согласованы расходы и запуск.
- Нет открытых блокеров безопасности/данных/оплаты/основного сценария; остальные улучшения записаны в один backlog P2 и не мешают релизу.
- Не добавлять ещё функции после выполнения этих условий. Разрешены только исправления дефекта, подтверждённого тестом/пилотом. Новые хотелки — отдельная версия.

Формат последнего отчёта: buildId, commit/diff, URL и bot username, что проверено автоматически/в настоящем Telegram, команды и exit/counts, снимки, подтверждение восстановления копии, business approvals, блокеры. Статус — `READY FOR FREE PILOT`, `READY FOR PAID PILOT` либо `BLOCKED`, не общий «всё идеально».

## 11. Риски, tradeoffs и остающиеся вопросы

1. **Текущая публичная версия неизвестна.** Сначала A01–A03. Не задавать новый большой опрос о вкусе: визуальные предпочтения уже есть.
2. **Отчёт P0 не соответствует прочитанным файлам.** Сначала честный gate и реальные regression, не принимать массовый зелёный отчёт без следов исполнения.
3. **5 000 ₽ — предел денежных вложений, не доказательство оплаты всего труда.** Смета должна показать обязательные денежные расходы и отдельно труд/внешнее ожидание. Перерасход — ручное решение, не обещание «потом окупится».
4. **Правовая и платёжная применимость не установлена.** Россия, статус продавца, personal-data storage, вознаграждения Stars и возвраты требуют проверки для реального владельца. Здесь нет юридического заключения и нет совета обходить Telegram внешней оплатой цифрового доступа.
5. **Готовой методологии/эксперта нет.** Не включать персональные цели, медицинские протоколы и выдуманные нутриенты ради красивой карточки. Проверка обычного рецепта и медицинская экспертиза — разные вещи.
6. **SQLite достаточность — ограниченный пилот, не обещание масштаба.** Один хост/постоянный диск/короткие транзакции; нагрузочный профиль согласовать. Не добавлять PostgreSQL заранее.
7. **Session cookies в реальном WebView нужно проверить.** Same-origin, HTTPS, CSRF, Secure; не решать cookie-проблему открытием CORS и передачей user_id от клиента.
8. **SDK и документация могут опережать друг друга.** Проверять новые subscription updates в pinned PTB fixtures; ограниченная совместимая правка возможна после отдельного теста, не global major update.
9. **Платёжный и дневниковый минимум после удаления.** До продаж согласовать, что удаляется сразу, что необходимо хранить и как об этом сообщается; не фабриковать исполненное удаление.
10. **Доставка внешних сообщений не exactly-once.** Условие и unknown-статус описаны в §6; не заменять это обещанием без механизма.
