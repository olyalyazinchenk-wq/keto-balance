# «Кето Баланс»: премиальный UI и короткий путь к проверяемому результату

> **For Hermes:** Use subagent-driven-development for bounded implementation tasks. Один интегратор пишет пересекающиеся файлы; независимый reviewer проверяет результат. Текущий документ — план, не выполненная реализация.

**Goal:** превратить уже сделанный Argon UI в одну полезную сборку основного «Кето Баланс», показать её владельцу в согласованной среде и отдельно подтвердить реальный Telegram-путь, не начиная новый rewrite.

**Architecture:** основной React 18/Vite 5/Tailwind 3 + Python/FastAPI/python-telegram-bot сохраняется. Из Argon переносится только выбранный презентационный слой через адаптеры реального домена; новый Express, демонстрационные данные и второй независимый runtime не становятся основным продуктом. Дизайн и сетевой доступ — разные направления работы с разными критериями приёмки.

**Tech Stack:** существующий основной стек, существующий Node test runner/TypeScript, CSS variables; без новых UI-фреймворков и motion-библиотек.

**Статус документа:** анализ завершён, два независимых read-only ревью получены; ключевые замечания перепроверены родителем по исходникам. План готов к ограниченному исполнению после назначения одного владельца пересекающихся файлов. Продуктовые проверки/сборка в этом плановом ходе не запускались.

## 2. Главный диагноз

Не нехватка моделей и не нехватка референсов. Одновременно существуют основной legacy UI, новая визуальная песочница, старая релизная сводка и несколько очередей работ. Изменения в песочнице ещё не равны изменению приложения, которое открывает пользователь.

**Остановить расширение вариантов. Следующий принимаемый результат — одна интегрированная вертикаль: Сегодня → Меню → Рецепт → Покупки, с сохранённым доступом к личной поддержке.** Дневник и остальные разделы не переписывать одновременно; подключать после этой вертикали.

Сеть/публичный HTTPS не чинится новым цветом кнопки. Красивый browser preview не закрывает M0; и наоборот, сетевой blocker не требует приостанавливать безопасную локальную UI-интеграцию.

### Перепроверенные находки независимых ревью

1. **Самая важная проблема — не цвет.** `src/App.tsx:161–175` продолжает использовать собственный `genMenu`: без проверки аллергий и со слотами по категории рецепта. Доменный `src/domain/menu.ts:42–75` уже фильтрует через `isRecipeAllowed`, но основной UI его не использует. Прежде чем сделать этот результат красивее, нужно подключить правильный путь данных.
2. **Два несовместимых каталога/контракта.** Основной монолит содержит собственный каталог; импорт нового экрана поверх него не делает подключённым `src/data/recipes.ts`. Argon DayMenu с `dayIndex/label` не тождественен основному с `date`.
3. **Покупки нельзя принять по кнопке обновления.** В Argon `.cache/argon-src/src/App.tsx:446–449` только снимает stale-флаг и передаёт старые items. В основном `src/App.tsx:177–179` количества извлекаются первым числом, без нормализации единиц; холодильник и вычитание используют разные поля состояния. Нужна настоящая пересборка, не только новый вид.
4. **Новый ложный success, уже без скрытой отправки.** `.cache/argon-src/src/components/kb/RecipeAndShoppingScreens.tsx:376–386` показывает копирование успешным даже при отсутствии/ошибке Clipboard API. Это не прежний дефект отправки на чужой ID; исправить актуальную причину отдельно.

Не принято как дефект: имя Ольги в личной поддержке. Пользователь явно потребовала личную связь с Ольгой; самостоятельный бренд не запрещает назвать человека на экране поддержки. Не заменять его вымышленным специалистом или каналом.

## 3. Выбранное направление: кулинарный продукт, а не музейный каталог

Сохранить из нового Argon:

- бренд «Кето Баланс», тёплый нейтральный `#F7F6F2` и глубокий зелёный `#165B40` как рабочую основу;
- аккуратные разделители, спокойную иерархию, читабельную кириллицу;
- пять разделов Сегодня / Меню / Покупки / Дневник / Ещё;
- поддержку до анкеты, явное demo-состояние, отсутствие вымышленных БЖУ;
- двухколоночные строки ингредиентов, достаточные зоны нажатия, честные состояния ошибок.

### Что изменить адресно

Просмотрены `mobile-today.png`, `mobile-menu.png`, `mobile-recipe.png` нового локального снимка. Это визуальный анализ этих изображений, не независимый тест браузера.

1. **Вернуть ширину содержимому на мобильном.** Постоянная левая индексная колонка отнимает место у длинного русского названия блюда. На 320–430px основная композиция одноколоночная; время/тип приёма пищи — короткая строка метаданных. Асимметрия допустима на desktop, не обязательна на телефоне.
2. **Убрать язык редакционного производства из пользовательских действий.** «Редакционное расписание», «главная подача момента», «выпуск дня» заменить на «Меню на …», «Ближайший приём пищи»/«Что приготовить». Сохранять стиль, а не заставлять человека разгадывать концепцию.
3. **Сократить служебную шапку.** У пользователя бренд + помощь в одной строке. Переключатели темы/сценариев, «до выбора/меню выбрано», «проверить конфликт» — только изолированный design/debug режим. Demo-предупреждение не скрывать до реальной интеграции: сделать компактным, но читаемым и однозначным.
4. **Еда — главный визуальный материал.** Для первого среза нужны изображения нескольких реальных стартовых блюд с подтверждённым происхождением, а не весь фотокаталог сразу. Без подходящих фото использовать спокойную честно названную иллюстрацию. Не выдавать схемы тарелки `Ø 240 мм` за премиальную фуд-фотографию и не скачивать чужие ассеты ради красивого screenshot.
5. **Показывать пользу выше декора.** На «Сегодня» до основной прокрутки понятны ближайшее блюдо, время и действие. На «Меню» виден хотя бы один приём пищи, а не только многоэтажное оглавление дней. На рецепте — понятный старт готовки, порция и путь к ингредиентам.
6. **Нижняя панель не перекрывает контент.** Требуется реальное измерение последнего focusable-элемента после прокрутки до конца, с safe-area и клавиатурой. Один screenshot с нижней обрезкой ещё не доказывает недоступность всего содержимого; надо проверить достижимость в браузере.
7. **Premium означает связность и заботу:** предсказуемый возврат, сохранённый черновик, быстрые списки, человеческие ошибки, понятный следующий шаг, качественные изображения. Не добавлять позолоту, постоянные анимации, огромные засечки и faux-print украшения ради «дороговизны».

### Что НЕ делать с Kami/Atelier Zero

`docs/design/references/DESIGN-kami.md:4–23` описывает преимущественно печатную/редакционную систему, а не мобильный UI. Четыре уровня текста там — прежде всего цветовая иерархия, а не запрет на необходимые размеры/семантические роли.

`DESIGN-atelier-zero.md:26–42, 84–89` предлагает приёмы журнала: координаты, римские главы, гигантскую типографику, шум бумаги. Не делать их обязательными элементами ежедневного кулинарного инструмента. Заимствовать дисциплину сетки и сдержанность, но не бумажный шум, кроп-марки и метки Plate Nº как самоцель.

Один новый `DESIGN.md` продукта должен разрешить расхождения. Внешние reference-файлы не могут одновременно диктовать несовместимые правила.

## 5. Организация команды: не создавать второй оркестр

На машине найдены профили `default`, `keto-dev`, `keto-content`, `office`; наличие роли в тексте не создаёт профиль. DeepSeek обнаружен как модель существующей Telegram-сессии, а не отдельный профиль с таким именем.

### Назначение ролей

- **DeepSeek, уже ведущий дизайн-чат:** единственный отправитель заданий текущему Argon; передаёт последний ref, результат проверки и конкретный список изменений. Не запускать параллельный «новый контекст» AI Studio от этого чата.
- **Argon / AI Studio:** ограниченный последний UI-проход по разделу 3, затем экспорт presentation-компонентов. Не backend, не правила питания, не инфраструктура.
- **`keto-dev`:** один интегратор в основном проекте. До старта установить, какая существующая сессия сейчас владеет `src/App.tsx`, `package.json`, styles и bot-файлами; роли «DeepSeek» и «keto-dev» могут быть одной работой, не считать их независимыми писателями без проверки.
- **`default` / независимый reviewer:** проверяет diff, контракты, путь пользователя и доказательства; не переписывает App параллельно интегратору.
- **`office`:** происхождение и статус материалов/изображений только из согласованной папки/каталога, без чтения медицинских дневников участников.
- **`keto-content`:** текст интерфейса/материалы по контракту; не пишет приложение и не меняет release gate.

Новые боты/профили не нужны для начала. Bot Mode по официальной документации — представление существующих профилей, не самостоятельное доказательство дополнительных моделей или доступа. Групповой чат моделей не заменяет владельца файлов, проверку и бюджет.

## 7. Внешний доступ и M0 — отдельный ограниченный пакет

- Не повторять две уже исчерпанные tunnel-попытки по инерции. Новое решение о транспорте должно иметь конкретную причину и согласованный лимит.
- Сервера у владельца нет. VPN-серверы не считать площадкой продукта.
- Возможный промежуточный результат: статический HTTPS design-preview без персональных данных, публикация только после явного согласования аккаунта/сервиса/объёма. Это НЕ приёмка backend/ownership и не автоматическая замена прежнего M0-контракта.
- Полный M0 принимается по прежним наблюдаемым критериям: владелец открыла нужную сборку в настоящем Telegram, несекретный вопрос дошёл Ольге лично, ответ вернулся. Серверный HTTP probe и real-client доказательства не смешивать.
- Для оплачиваемого размещения и постоянных ресурсов — один отдельный запрос владельцу с полной стоимостью и ограничениями. Общий бюджет 5 000 ₽ не разрешает покупать автоматически.
- В этом ходе решения о публикации/размещении не принимались, реальные отправки не выполнялись.

## 8. Критерии остановки — чтобы разработка не стала бесконечной

### Приёмка первого UI-пакета

- [ ] Одна зафиксированная версия UI; нет A/B/C controls в рабочем пути.
- [ ] На телефоне нет постоянной пустой индексной колонки и непонятных редакционных команд.
- [ ] Сегодня → Меню → Рецепт → Покупки работает на реальных идентификаторах основного каталога.
- [ ] Строки ингредиентов/данные порций не выдуманы; неизвестное не превращается в нули.
- [ ] Черновик и выбранный день сохраняются, помощь до анкеты работает.
- [ ] Нижняя панель/клавиатура не делают действия недоступными; светлая/тёмная темы читаемы.
- [ ] Нет новых внешних запросов, оплаты, фоновых рассылок, скрытой отправки и демо-истории под видом пользователя.
- [ ] Указан актуальный build ID, реальные команды, exit codes и отдельный объём browser/Telegram проверок.
- [ ] Внепакетные файлы/изменения владельца сохранены; commit/push/deploy не выполнялись без отдельного разрешения.

После этого: портировать ручной дневник/Ещё тем же способом, затем gate безопасного бесплатного пилота по ранее утверждённому release-плану. Оплата/подписка/защищённая админка — следующий отдельный пакет, не часть «покрасить UI».

**Не основание для новой полной итерации:** желание ещё одной палитры, трендовый шрифт, новый каталог вдохновения, новый агент. Только конкретный дефект, измеримое улучшение пути или утверждённое владельцем изменение продукта.
