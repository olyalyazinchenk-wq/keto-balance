Полный минимальный helper для чистых TS-модулей (не загружать через него весь App.tsx):

```js
// tests/helpers/load-ts.cjs
const fs = require('node:fs');
const path = require('node:path');
const vm = require('node:vm');
const { createRequire } = require('node:module');
const ts = require('typescript');
function loadTs(file, cache = new Map()) {
  const absolute = path.resolve(file);
  if (cache.has(absolute)) return cache.get(absolute).exports;
  const module = { exports: {} };
  cache.set(absolute, module);
  const nativeRequire = createRequire(absolute);
  const localRequire = name => {
    if (name.startsWith('.')) {
      const base = path.resolve(path.dirname(absolute), name);
      for (const candidate of [base, `${base}.ts`]) {
        if (candidate.endsWith('.ts') && fs.existsSync(candidate)) return loadTs(candidate, cache);
      }
    }
    return nativeRequire(name);
  };
  const output = ts.transpileModule(fs.readFileSync(absolute, 'utf8'), {
    compilerOptions: { target: ts.ScriptTarget.ES2020, module: ts.ModuleKind.CommonJS },
  }).outputText;
  vm.runInNewContext(output, { module, exports: module.exports, require: localRequire,
    Date, Math, structuredClone, console }, { filename: absolute });
  return module.exports;
}
module.exports = { loadTs };
```

Sandbox-объекты имеют другие прототипы: проверять отдельные значения либо нормализовать результат для deep equality. Transpile не проверяет типы; поэтому typecheck обязателен отдельно. Не давать helper сетевые функции, DOM, доступ к реальному localStorage или настоящую БД.

## P09. Консервативный сценарий симптомов без медицинской самодеятельности

**Создать:** src/domain/safety.ts, bot/safety.py, tests/frontend/safety.test.cjs, tests/backend/test_safety.py.
**Изменить:** src/App.tsx и bot/bot.py — только маршрутизацию/guards, не нутриентные формулы.

**Граница:** это технический fail-safe локального прототипа, не диагностическая система и не доказательство надёжного распознавания любых симптомов. Новую медицинскую карточку и универсальные клинические правила исполнитель не утверждает.

1. Использовать явную кнопку «Мне нужна срочная помощь» и существующие RED_FLAGS как достижимые отметки. Нельзя полагаться только на свободный текст.

Похожие слова без контекста не считать полной диагностикой. Для неоднозначного/отрицательного контекста — нейтральное уточнение без советов о диете; не обещать нулевые false-negative.
3. В frontend вводит persisted safetyHold с явным полем причины/времени, без диагноза. Любое срочное действие активирует hold до рендера следующего совета. Таймер ожидающего обычного ответа отменить/проверить повторно перед добавлением ответа.
4. При hold блокировать автоматические меню/замены/конструктор/программы/диетический чат; доступ оставить к карточке помощи, настройкам и проверке ошибочно сделанной отметки. Снятие ошибочной отметки не обозначать «вы здоровы». Reload и смена дня сами hold не снимают. Минимальная миграция состояния добавляет только безопасный default для safetyHold и отсутствующих полей, без общего рефакторинга store.
5. Для явного запроса срочной помощи показывать существующую экстренную информацию проекта отдельным экраном, без советов по еде/электролитам и без имитации вызова скорой/уведомления организатора. Пометить контент как требующий проверки по региону до публикации; номера 112/103 не объявлять универсальными для всей аудитории.
6. В боте проверка safety выполняется до обычных текстовых triggers. При срабатывании ставить runtime hold в context.user_data и отвечать информацией о необходимости срочной медицинской помощи. Общий guard должен покрыть все обработчики диетических рекомендаций и callback. Не отправлять персональные симптомы в общий чат.
7. Пока нет утверждённой методологии и общего постоянного safety-state, публичные персональные расчёты/плато/электролитные протоколы не включать. В локальном P0 временно отвечать «Персональные рекомендации временно недоступны» в /calc и путях, выдающих такие протоколы; не переписывать calculate_nutrition. Просмотр общего каталога в боте не называть персональной рекомендацией; при runtime hold не выдавать его как следующий совет.
8. В отчёте прямо записать: frontend и бот ещё не синхронизируют safetyHold; бот без настроенной persistence теряет runtime hold при перезапуске. Не добавлять миграцию рабочей БД ради маскировки ограничения. Это блокер публичного медицинского сопровождения, но не причина выдумывать готовую защиту.

Тесты: каждый явный срочный кейс; смешанный запрос «кето + боль в груди»; приоритет safety над приветствием; ввод во время typing timeout; checkbox и прямой hash; reload; возможность исправить ошибочную отметку; бот callback после hold. Негативные контексты проверять отдельно. Один regex не является доказательством клинической безопасности.
