## Замечания по приоритетам

### 1. Общий gate пока не fail-closed

`scripts/verify-p0.py:42–48`: отсутствие backend-тестов только печатает INFO, а не блокирует проверку.
`scripts/verify-p0.py:72–80`: отсутствие tests/e2e/p0.spec.ts пропускает E2E, после чего может быть напечатано `All P0 verifications passed!`.

Сегодня скрипт корректно падает на backend. Но после исправления P03 может сообщить общий успех без браузерной проверки. Нужны отдельные явно названные checkpoint/full режимы либо единственный полный gate, который возвращает nonzero при отсутствии любого обязательного набора. Default полного gate — fail-closed. Неполный checkpoint никогда не печатает «весь P0 пройден».

Добавить тесты самого runner: пустой backend, отсутствующий E2E, nonzero дочерней команды, корректный полный набор. Во время проверки политики runner допустимо подменять subprocess, но это не заменяет настоящий финальный прогон.

### 2. Регрессионный тест чтения .env недостаточен

`tests/backend/test_import_safety.py:29–51` проверяет, что импорт завершился и BOT_TOKEN существует. Он не фиксирует фактическое отсутствие открытия .env. Если guard впоследствии убрать, импорт способен пройти, прочитав файл.

Добавить свежий subprocess с запретом открытия .env и sqlite3.connect/socket.connect при импорте. Не открывать настоящий .env для сравнения. Проверить config/database/payments/bot/server; запрещённая попытка должна проваливать тест, даже если импортируемый код перехватывает исключение. Текущая реализация такой независимый probe уже прошла, но этот контроль нужно сохранить в test suite.

### 3. Полный backend не зелёный

`tests/backend/test_payment_callbacks.py`:
- test_buy_callback_returns_disabled_notice — FAIL: старый callback вызывает init_purchase.
- test_plateau_keyboard_has_no_buy_button — FAIL: осталась buy_plateau_guide.
- test_confirm_demo_callback_returns_disabled_notice — ERROR: mock возвращает MagicMock, старый путь доходит до обращения к PRODUCTS и вызывает KeyError.

Последняя ошибка — несовершенная диагностическая форма RED, а не подтверждение изменения настоящего заказа. Улучшить тест: заменяемая forbidden-функция должна сразу вызывать AssertionError при обращении, чтобы RED падал на нарушении запрета, а не на случайном MagicMock/KeyError. После исправления удалить legacy-импорты; тесты не должны требовать наличия удалённого импорта только ради patch.

В реальном callback текущие payments-функции выбросят RuntimeError без пользовательского безопасного ответа. Поэтому закончить отключение UI/callback, а не считать остановку платежей завершённой по unit-тестам двух функций.

### 4. Прогресс и качество отчёта

docs/p0-progress.md всё ещё показывает 6 backend tests, а отчёт исполнителя показывает 9 из выбранных файлов. Полный discovery уже запускает 12 и не проходит. Журнал нужно актуализировать и всегда отделять выбранный зелёный subset от полного набора.

git diff --check сообщает две ошибки EOF. Удалить только лишние пустые строки, не менять форматирование модулей целиком. Предупреждения LF/CRLF не путать с этими ошибками.
