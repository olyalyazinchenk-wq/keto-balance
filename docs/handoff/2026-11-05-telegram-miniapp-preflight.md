# КетоБаланс — Telegram Mini App: безопасный тестовый переход (2026-11-05)

## Основание

- Рабочая ветка `feat/cloudru-real-teardown-and-backup-hardening`, baseline [9f04fa1](https://github.com/olyalyazinchenk-wq/keto-balance/commit/9f04fa1b126e932870d56c8c47d68cb6d662c1e4).
- [CI 41970841459](https://github.com/olyalyazinchenk-wq/keto-balance/actions/runs/41970841459) на baseline: success. Этот результат **не подтверждает** новый PR.
- Пользовательский путь: кнопка бота (private chat) → HTTPS WebApp → `Telegram.WebApp.initData` → `POST /api/session` (HMAC + проверка свежести на сервере, `owner_allowlist`) → gate 18+/согласие → меню, покупки, повторный вход.
- Источники протокола: https://core.telegram.org/bots/webapps и https://core.telegram.org/bots/api (WebAppInfo HTTPS), https://docs.telegram-mini-apps.com/platform/init-data (валидация на сервере).

## Что адресно исправлено

1. Клиент теперь использует приоритет подписанного `Telegram.WebApp.initData` над тестовым `demo_user`, если оба попали в адрес. Никакое `initDataUnsafe` не становится доказательством личности.
2. Разбор `tgWebAppData` поддерживает обычный Telegram hash и hash-навигацию `#/route?tgWebAppData=`; неизвестные/некорректные `demo_user` не подставляют произвольный ID.
3. `setupTelegramApp` и очистка слушателей вызываются через один React effect, без второго безусловного запуска при импорте файла.
4. Убран непроверенный конкретный username бота из текста при отказе в авторизации.

**Изменения не переключают кнопки, не запрашивают/не выводят токены, не открывают доступ посторонним, не включают оплату или внешнюю инфраструктуру.** Демо-маршрут /api/demo-session сервером доступен только при `allow_demo_auth` и `app_stage == test`.

## Блокеры

- Текущий `WEBAPP_URL` по умолчанию `http://localhost:5173`. Это не HTTPS и не работает для открытия WebApp внутри Telegram. Проверен путь конфигурации, **не проверен реальный URL**.
- Не утверждены сервер, домен и расходы; грант Cloud.ru не активировался по сообщению владельца, биллинг без API **UNKNOWN**.
- Нет доказательства реального теста двух Telegram-кнопок и открытия внутри настоящего клиента Telegram.
- Отчёт `docs/release/catalog-validation-report.json` для baseline `9f04fa1` показывает **50 PASS, 0 WARN, 0 ERROR**, но **максимальное** отличие заявленных калорий от формулы Этуотера по всему каталогу составляет **26 ккал**, среднее — **11,1 ккал**. Заявление «не более 4 ккал для всех 50 блюд» неверно; не распространять точность четырёх новых завтраков (разница 0–4 ккал) на весь каталог.
- Формула Этуотера доказывает лишь арифметическую согласованность заявленных КБЖУ, но не состав или пищевую ценность ингредиентов; релизный статус рецептов остаётся pending.
- Не создавать внешние ресурсы, не писать токены в GitHub, не менять `master`, существующего бота и Home Pilot. До согласования — только автономный offline/synthetic тест.
