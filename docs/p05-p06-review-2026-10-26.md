## Обязательные исправления до интеграции нового меню

### 1. Новый результат меню несовместим с существующим приложением

`src/domain/menu.ts:13–25,99,112`:
- slots содержит целые Recipe-объекты;
- created — ISO-строка.

Существующий `src/App.tsx:173,176,277` использует slots как recipe ID-строки и created как числовое время. В независимой пробе typeof slot === object; старый lookup RECIPES.find(r => r.id === slot) не находит рецепт. Просто подключить generateMenu в текущий UI нельзя: будет несовместимый объект, возможное падение при чтении r.title и некорректные покупки.

Согласованный минимальный контракт: days[].slots = Record<string,string> с ID; created = number (timestamp). Сохранить mode/meals/portion/saved/days. Исправить тесты так, чтобы они проверяли совместимость с потребителями, а не утверждали новый несовместимый формат.

### 2. Замены не ограничены режимом текущего меню

`src/domain/menu.ts:117–136`: replacementCandidates не проверяет r.mode. Вызов для текущего k2, profile.mode=keto и полного RECIPES вернул кандидатов двух режимов, включая 16 carnivore.

До P07 ввести явный mode в контракт замены и брать его из текущего menu.mode. Проверять одновременно режим, занятые id, профильные ограничения и допустимые категории. Нельзя полагаться на случайно предварительно отфильтрованный массив в одном UI-вызове.

### 3. Плохой формат ограничения превращается в отсутствие аллергии

`src/domain/eligibility.ts:159–175`: allergies не-массив заменяется на []. Проба k2 с allergies=['Яйца'] вернула false, с allergies='Яйца' — true.

Такой вход не соответствует TypeScript-интерфейсу, но старый localStorage загружается без runtime-валидации. Поэтому до рекомендации нужно валидировать данные: некорректный формат ограничений означает отказ/уточнение, не отсутствие ограничений. Не исправлять это медицинскими догадками или новым словарём опечаток.

### 4. Неизвестный состав ингредиента автоматически допускается

В функции isRecipeAllowed неизвестные названия, не совпавшие с ключевыми словами, считаются допустимыми. Синтетический рецепт с ингредиентом «Неизвестный состав соуса» при заявленной яичной аллергии вернул true.

Это не утверждение, что соус содержит яйца. Это отсутствие информации, которую нельзя превращать в подтверждённую совместимость. Ввести явную классификацию/статус состава для используемых ингредиентов; при активных аллергиях непроверенный состав блокирует автоматическую рекомендацию до уточнения. Не обещать отсутствие следов аллергенов.

## Важное разграничение: модули ещё не интегрированы

На момент проверки App.tsx:
- по-прежнему содержит собственные Recipe/RECIPES и старый genMenu;
- не импортирует src/data/recipes и src/domain/menu;
- использует старые предложения и замены.

Поэтому тесты новых модулей подтверждают работу отдельных функций на текущих fixtures, но не исправление поведения приложения. Это нормально для незавершённого P07, но P05 нельзя считать полным «выносом» данных, пока в UI остаётся независимая копия. Каталог с исправленной меткой k4 пока не является источником текущего UI.
