## Где исправлено

- `src/ui/food-first/model.ts:13–15`: `photoForRecipe` возвращает asset только для известного ID; для скрэмбла и неизвестного ID — null.
- `src/components/kb/TodayAndMenuScreens.tsx`: реальный Today использует `photoForRecipe(leadRecipe.id)`, а не одну фотографию для любого блюда.
- `src/utils/clipboard.ts`: Promise ожидается; reject/отсутствующий API возвращают false.
- `src/components/kb/RecipeAndShoppingScreens.tsx`: UI показывает успех только после успешного результата; для ошибки есть `role=alert`.
- `src/utils/shoppingFromMenu.ts`: список строится по актуальным дням/слотам и исходным ingredient.amountLabel; неизвестный рецепт/неполный ингредиент вызывают ошибку. Личные позиции и точно совпавшие отметки сохраняются по предусмотренному контракту; соответствующий unit-тест прошёл.
- `src/App.tsx`: после успешного rebuild обновляются items, затем снимается stale; в catch stale остаётся true.
- `src/components/kb/RecipeArtwork.tsx`: удалён PLATE_META с эффектами, процентами и весами; вместо него честное состояние отсутствующей фотографии.
- `src/components/kb/RecipeAndShoppingScreens.tsx`: вместо ~230/~460 г показано число порций.

## Почему покупки ещё не завершены

В проверенном rebuild ингредиенты идут отдельными строками из каждого рецепта/слота; amountLabel не суммируется и не переводится в другую единицу. В воспроизведённом примере получилось 33 исходные строки. Это исправляет прежнюю ложную синхронизацию, но не является проверенной продуктовой нормализацией.

Не проверены здесь универсальная агрегация продуктов, преобразование единиц, общая семантика порций и pantry, миграция отметок из старого fixture-списка и поведение на всём каталоге основного приложения. Не заменять эти проверки словом «готово».

## Как проверялся preview

Существующий `127.0.0.1:4387` отвечает HTTP 200 и отдаёт production entry `/assets/index-F24MKrl7.js`. SHA-256 served JS:

```text
ae611d54a65ccdb5f35267ecd9dbfa99037864a2e463ea044078a9f4df474461
```

Его байты совпали с независимой сборкой текущих исходников. Запрос `/src/App.tsx` на таком SPA-preview возвращает HTML fallback, а не TypeScript: HTTP 200 этого маршрута нельзя использовать как проверку исходного файла.

Проверка браузера — отдельная свежая сессия, viewport 390×844, только synthetic fixtures. Неперехваченные ошибки/unhandledrejection в проверенных действиях не зарегистрированы; полный аудит console и всего пути не выполнялся.

## Граница приёмки и следующий приоритет

1. **Принимается:** исправление соответствия фото, честного копирования и реального rebuild списка в локальном прототипе; удаление указанных обещаний из указанных компонентов.
2. **Не принимается как завершённое:** нормализация покупок и весь контент. Source-check сканирует конкретные файлы/фразы, не доказывает безопасность всех материалов; прежние out-of-scope forecast-функции не стали валидированными медицинскими расчётами.
3. **Остаётся:** единый food-first стиль Menu/Recipe/Shopping, полный сценарий с сохранением состояния, перенос presentation/adapters в основной проект, отдельная Telegram-приёмка.
4. **Не переносить целиком:** donor package.json, React19/Tailwind4/Express и сокращённые domain types поверх основного стека/домена.

Это ревью, не поручение на новые продуктовые правки и не разрешение на commit/push/deploy. Telegram, реальные сообщения, оплаты и рабочие данные в проверке не использовались.

Preview был запущен исполнителем раньше: ревьюер его не запускал, не перезапускал и не останавливал.
