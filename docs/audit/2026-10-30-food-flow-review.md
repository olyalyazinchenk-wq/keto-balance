## Остаточный дефект: выбор дня не восстанавливается

**Источник:** `design/argon-food-first-work/src/App.tsx:138`: `useState<number>(1)` для `selectedDayIndex`, без сохранения и восстановления этого курсора.

**Воспроизведение в браузере:**

1. Открыть Menu и выбрать «День 2 · Простые домашние блюда».
2. Полностью перезагрузить документ.
3. Открыть Menu снова.
4. Активным становится «День 1 · Спокойный старт».

Не путать это с потерей изменённого меню: **изменения слотов и покупки сохранились**, потерялся выбранный день. Поэтому утверждение о сохранении данных подтверждено, но полное восстановление пользовательского контекста — нет.

**Следующее узкое исправление:** сохранять selectedDayIndex прототипа и восстанавливать его только после проверки наличия соответствующего дня в актуальном меню; для удалённого/невалидного дня выбирать доступный fallback. Добавить browser-проверку выбора непервого дня → reload → тот же день/рецепт, при неизменных покупках. В основном проекте использовать его канонический контракт даты/ID, не подменять дату номером прототипного дня.

Продуктовые правки ревьюером не выполнялись.

## Границы приёмки

- Общая оболочка для четырёх экранов есть в `AppShell.tsx:72–108`.
- Menu использует `menu-food.css`; Recipe/Shopping — `recipe-shopping-food.css`. Старый визуальный код для остальных маршрутов может оставаться: их redesign не был предметом этого этапа.
- В `App.tsx:597–602` выбор меню вызывает настоящий `handleRefreshShoppingFromMenu()` до перехода в Shopping. Browser-проход подтверждает действие, а не только наличие вызова в source.
- Покупки остаются отдельными исходными строками на порцию [1], без согласованной нормализации единиц/общей семантики порций/pantry. Эта часть не принята как основной продукт.
- Безопасность подбора, достоверность всего контента, реальный транспорт поддержки и открытие в Telegram этим прогоном не приняты.
- Перенос в основной проект не выполнялся. Не копировать donor React19/Tailwind4/Express, fixtures и упрощённые domain types поверх основного приложения.

Практический следующий этап: закрыть восстановление выбранного дня, зафиксировать этот локальный checkpoint и перейти к ограниченной интеграции через реальные данные/адаптеры. Не открывать новый конкурс концепций и не называть прототип коммерческим релизом.
