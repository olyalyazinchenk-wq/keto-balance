# Общий контекст и порядок работы КетоБаланса
Принято по прямому поручению Ольги 12.11.2026: устранить расхождения между моделями и регулярно поддерживать единый контекст.

## Единственный источник текущего состояния
1. docs/CURRENT-STATE.md — текущая сводка, доказательства, неизвестные и следующий шаг.
2. GitHub Issues/PR — задачи, обсуждения и результат работы; Git SHA — идентификатор исходников.
3. docs/HANDOFF-LOG.md — короткий журнал передач; исторические документы не являются текущим статусом.
4. Notion-хаб — зеркало/навигация с датой сверки и ссылкой на GitHub. Старые записи — история.
Не поддерживать второй независимый статус в чатах, Notion, CLAUDE.md или GEMINI.md. Google Drive не использовать.

## Вход любой модели (GPT/Codex, Antigravity/Gemini, Claude)
- Получить свежие origin/master и рабочую ветку обычным git fetch; ничего не reset/rebase/overwrite автоматически.
- Прочитать AGENTS.md → docs/CURRENT-STATE.md → этот файл → соответствующую Issue/PR и последний handoff.
- Сопоставить локальную ветку и SHA с удалёнными. Наличие новых документов в master не делает старое приложение релизным.
- Перед продуктовой правкой назвать задачу, ветку, исходный SHA, окружение, затрагиваемые файлы и критерий готовности.
- Если последние локальные изменения не доступны в GitHub, сначала сохранить/сопоставить их. Не начинать новую реализацию того же функционала из старой master.
- Если источник недоступен, отметить «контекст не проверен»; можно готовить предложения, нельзя объявлять сервер/релиз исправным.

## Координация без конфликтов
Одна активная реализация на одну Issue. Исполнитель оставляет в соответствующей Issue/PR короткую запись «Взято», имя среды/модели, ветку, baseline SHA, область файлов и время (ISO 8601 с timezone). Проверить, нет ли уже активного исполнителя.
Непересекающиеся задачи могут идти независимо; общие файлы и переключение бота координирует один исполнитель.
Если исполнитель пропал, работа не считается автоматически свободной: следующий сначала проверяет ветку/PR, сохраняет результаты и явно фиксирует передачу.
Это организационный протокол, а не техническая блокировка чужих процессов.

## Завершение каждого существенного шага
В той же ветке/PR, что и изменения:
- Обновить CURRENT-STATE (что действительно изменилось, что осталось неизвестным).
- Добавить handoff: задача, автор/модель, base/head SHA, окружение, проверка и ссылка/результат, блокер, следующий шаг.
- Записать отдельно source SHA, deployed SHA, build ID, catalog hash; неизвестное = UNKNOWN. Никогда не помещать секреты.
- Done допустим только по критерию приёмки; «реализовано», «проверено локально», «CI», «развёрнуто», «принято владельцем» различать.
- Перед передачей проверить, что коммит доступен в GitHub. Нельзя давать серверному исполнителю ссылку только на локальный SHA.
- После интеграции обновить каноническую сводку master. Незавершённые PR отражать как незавершённые, не как выпущенные.

## Повторная проверка
Один успешный набор проверок на неизменном SHA достаточен. Повторять при новых изменениях, сбое или конкретном неустранённом риске.
Не делать новые аудиты вместо устранения известного блокера. Не добавлять функциональность за рамками первого пилота до его приёмки.

## Автоматическое обновление
Запрошена регулярная сверка: каждый день утром и вечером по Москве. Использовать одну задачу ChatGPT Automations с доступом к подключённым GitHub и Notion; не создавать дублирующий GitHub Actions с Notion-токеном.
При каждом запуске:
1. Перечитать AGENTS/CURRENT-STATE/этот порядок, свежие refs/PR/CI/Issues и Notion-хаб.
2. Обновить только проверяемые факты в GitHub-сводке и коротком управляемом разделе Notion. Для записи GitHub использовать свежий blob SHA, отдельную docs-ветку/PR и разрешённую интеграцию; при конфликте перечитать, не перетирать.
3. Не считать master HEAD последним приложением: docs-only коммиты отделять от продуктовых.
4. Для локального/серверного отчёта сохранять пометку источника; без доступа не повышать статус до проверки.
5. При неизменном содержании не создавать пустых коммитов, новых PR/страниц и уведомлений.
6. При ошибке/конфликте сохранить последний подтверждённый статус, сообщить конкретный блокер. Не объявлять зеркало синхронизированным.
7. Не трогать секреты, данные клиентов, биллинг, тарифы, приложение, бота или деплой.
Автоматизация дополняет обязательное обновление исполнителем после работы и не видит несохранённые локальные правки. Внешнюю модель невозможно принудительно подключить к этой базе без её доступа и соблюдения входного протокола.
